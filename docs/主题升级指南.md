# nova 主题维护指南

> **用途**：本站已于阶段6 完成主题迁移——从「寄生在 `themes/butterfly/` 里改主题」改为
> 「自有主题 `themes/nova/`」。本文说明 nova 的结构、每类文件的来源与维护方式。
>
> **生成依据**：`node _snapshots\trace-pug.js`（追踪 Pug 引用闭包）+ `node _snapshots\build-nova-manifest.js`（分类清单）。
> 脚本与清单留在 `_snapshots/`，需要重新核算时可直接重跑。

---

## 一、为什么迁移

迁移前的状态是三类文件混在同一个目录里，无法分辨：

| 类别 | 数量 | 问题 |
|---|---|---|
| 站点自研/改动 | 12 个 pug | 看起来像"改过的主题文件"，实为站点自己的实现 |
| 主题原版仍在服役 | 164 个 | 正常工作，但身份不明 |
| 死代码 | 9 个 pug | 占着位置、误导后来者（含旧 head 全家） |

**实际踩到的坑**：做 head 本地化时以为改的是"主题的 head"，结果站点有**两套 head**
（定制 `_partials/head.pug` 服务 9 个页面、主题原版 `includes/head.pug` 服务 5 个页面），
只改了一套 → 文章页仍走 jsDelivr CDN 而无人察觉。

迁移后 `themes/nova/` 里的每个文件都有明确归属，且 **head 只剩一份实现**。

## 二、nova 结构

```
themes/nova/                        176 文件
├─ LICENSE                          ← Butterfly MIT 署名（必须保留, 见第四节）
├─ _config.yml                      ← 主题默认值（1132 行，来自 Butterfly）
├─ plugins.yml                      ← 第三方库 CDN 清单（实际由 CDN.option 覆盖）
├─ package.json  README*.md         ← 参考文件，Hexo 不使用
├─ languages/                       ← 7 个语言包（实际只用 zh-CN）
├─ scripts/                         ← 29 个：CDN 映射 / 默认配置 / 12 个标签插件 / helper
└─ layout/
   ├─ _partials/                    ← 【站点自有】
   │   ├─ head-content.pug          ← ★ 全站唯一的 head 实现（mixin）
   │   ├─ head.pug                  ← 18 行薄外壳
   │   └─ helpers.pug
   ├─ parts-common/                 ← 【站点自有】loading / sidebar / nav / footer / 评论 / 播放器（8 个 HTML 片段）
   ├─ base.pug  layout.pug          ← 【站点自有】两套外壳（含 head 调用）
   ├─ home-parts/ page-parts/ tag-parts/ idx-parts/ project-parts/  ← 页面 HTML 内容片段
   ├─ includes/                     ← 组件（head/ 只留 structured_data）
   └─ 14 个页面入口 pug             ← 404 about archive category home index moments music page post project-detail projects tag tags-index
```

### 两套外壳仍在，但 head 已统一

```
9 个 layout  →  base.pug  →  _partials/head.pug（薄外壳）→  head-content.pug
5 个 layout  →  layout.pug ─────────────────────────────→  head-content.pug
```

`base.pug` 的 shell（sidebar/footer/rightside）由**生成器注入**（`scripts/parts-common.js`）；
`layout.pug` 自己渲染 shell。**两者 head 完全共用**，改 head 只需改 `head-content.pug` 一处。

## 三、文件来源分类（决定怎么维护）

| 来源 | 判断方式 | 维护原则 |
|---|---|---|
| **站点自有** | `layout/_partials/`、`layout/parts-common/`、`base.pug`、`layout.pug`、`about/moments/music/project-detail/projects/tags-index.pug`、`includes/third-party/share/share-js.pug`、`scripts/` 里的站点改动 | 随便改，这是你的代码 |
| **取自 Butterfly（MIT）** | 其余 164 个（`includes/` 组件、`home-parts/` 等、`scripts/` 原版部分） | **原样保留**；要改就在注释里写明「本站改动」 |
| **已丢弃** | 见下节 9 个 | 不恢复 |

### 已丢弃的 9 个文件（旧 head 系统）

```
layout/includes/head.pug            ← 旧 head 主壳（被 head-content.pug 取代）
layout/includes/head/Open_Graph.pug      ← OG 标签改由 head-content.pug 内联输出
layout/includes/head/config.pug          ← GLOBAL_CONFIG 已内联
layout/includes/head/config_site.pug     ← GLOBAL_CONFIG_SITE 已内联
layout/includes/head/preconnect.pug      ← 已不需要（外部资源全部本地化）
layout/includes/head/site_verification.pug  ← 站点未使用
layout/includes/head/pwa.pug                ← 站点未使用
layout/includes/head/google_adsense.pug     ← 站点未使用
layout/includes/head/analytics.pug          ← 站点未使用（仅用 busuanzi，在 footer 里）
```

> 这 9 个文件的功能**已全部由 `_partials/head-content.pug` 覆盖或本就未启用**。
> 其中 `structured_data.pug` 是例外——它**仍在用**（文章页 `BlogPosting` 由它产出），
> 位于 `layout/includes/head/structured_data.pug`，被 head-content 引入。

## 四、Butterfly 授权

nova 中包含取自 [hexo-theme-butterfly](https://github.com/jerryc127/hexo-theme-butterfly)（MIT）的代码，
`LICENSE` 已随迁移保留。**不要删除 `LICENSE`**。

如需在文件头标注来源，用统一格式：

```
//- 取自 hexo-theme-butterfly v5.7.0 (MIT) —— 本站未改动
```

## 五、日常维护

### 改 head（最常见）

只改 `layout/_partials/head-content.pug` 一处，全站 14 个页面生效。

### 加页面级 SEO

在对应 layout 的 `block headOpts` 里加字段（`canonical` / `extraHead` / `articleTags` 等），
字段含义见 `head-content.pug` 顶部注释。

### 改主题默认值

**优先**在站点配置 `_config.nova.yml` 里覆盖，**不要**改 `themes/nova/_config.yml`——
后者是上游默认值，改了就失去"哪些是本站选择"的区分。

### 上游同步（可选）

nova 已不依赖 Butterfly 升级。若想把上游新特性拿进来：

```powershell
# 看上游改了什么（只针对"取自 Butterfly"的那 164 个文件）
npx --yes diff -r node_modules/hexo-theme-butterfly/layout themes/nova/layout
```

**只挑需要的移植**，不要整目录覆盖——那样会毁掉站点自有层。
